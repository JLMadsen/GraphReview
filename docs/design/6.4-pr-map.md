### 6.4 The PR map — a second view of the same diff (built 2026-09-24)

**Problem.** The module graph answers "where in the whole app does this change land?", but on a real repo it's 50–150 nodes with every import drawn. It doesn't answer "what is this change, as a picture?" The inspiration is the per-PR diagram in Steve Sanderson's NDC talk: four or five cards, each naming a *role in the change* ("FFI Lifecycle Coverage", "ffi-rs Runtime Host", "ffi-rs Dependency"), each listing its changed files with a status badge, joined by a few edges with verbs ("covers", "starts", "uses").

**What it is.** Once a diff is selected, the Graph tab's canvas slot has two views behind a **Repo | PR** switch:
- **Repo** — the existing Cytoscape graph, unchanged (touched/added highlighting still on).
- **PR** — the PR map: only the changed files, grouped into cards, with labelled edges, laid out left-to-right.

Both stay mounted (stacked in one grid cell, the inactive one transparent and `inert`, so Cytoscape keeps its size, layout and zoom; not `visibility: hidden`, which React Flow's inline `visibility: visible` on nodes pokes through). Selection is shared: clicking a card selects its component and opens the usual side panel; the panel and each card have **Show in repo** (switches view and pans to the component and its neighbours, resolving a collapsed domain to its box), and the panel has **Show in PR** when the selected component is on the map. File chips open the existing diff modal. The review dock stays under whichever view is showing, and findings mark cards (worst verdict + count) and chips (a dot). The last view chosen is remembered per browser; `pr` is the default.

**Level of detail.** About 2–8 cards per PR, 1–4 files each, every changed file on exactly one card; a name of 2–4 words, a one-line description; edges only where the code justifies one. Up to 6 faded **unchanged neighbour** cards (untouched modules the changed *code* imports or is imported by) give context, and are dropped once the map has 14 cards of its own. Above 12 edges, labels show only on the selected card's edges; stroke width carries the weight.

#### Two groupings over one set of links

`lib/jobs/pr-map.ts` does the work, in three pure steps over data loaded once (`loadPrMapInput`: the owning component of each changed file, and every `IMPORTS` edge into or out of a changed file, one hop):

1. **Classify** each changed file by path: `code`, `test` (`*.test.*`, `*_test.go`, `__tests__/`, `src/test/` …), `dependency` (manifests and lockfiles), `config` (CI, Docker, `*.config.*`, dotfiles, YAML/TOML), `docs` (prose).
2. **Collect file-level links** — the only source of edges: `import` (an `IMPORTS` edge touching a changed file; the far end is a changed file or, failing that, its owning component), `covers` (a changed test whose own module has changed code, when it doesn't already import changed code), and `uses` (a changed code line importing a package whose manifest entry this diff changed — package names are read from `package.json`/`composer.json`/`go.mod`/`Cargo.toml`/`requirements*.txt`/`pyproject.toml`/`Gemfile` diff lines; lockfiles contribute none).
3. **Assemble** cards and edges for *a grouping* (`assemblePrMap`): links are aggregated over whichever card holds each end, verbs come from the roles (`covers` from a test card, `uses` into a dependency card, otherwise `imports`), and context cards are picked by link weight.

- **Heuristic grouping** (`heuristicPrMapGroups`, no AI): one card per owning component for code, one per owning component for tests ("X tests"), one per top folder for files the analysis doesn't know yet, and one each for Dependencies ("Changes ffi-rs"), Build & config, and Documentation. Works for pasted paths too (no statuses or counts then). **As built (2026-10-06):** a code card of more than 8 files that is partly deleted splits into the files that stay and "X (removed)" — modules are folders, so one flat folder was one card however much of it a diff touched (PR #3 handed the model a 30-file `graph` card it then kept).
- **AI grouping** (`groupPrMap` in `lib/ai/pr-map.ts`): one call at the **end of every review job**, after the per-component calls, so their finding summaries can inform the names. Input: the stated intent, every changed file with its status, counts, heuristic card and a few changed declaration lines (`patchHighlights`), the heuristic cards, context cards and links by name, and the review's finding summaries. Output: groups `{name, description, files[]}` and edge verbs `{from, to, label}`. The model regroups and names; it **never decides which edges exist** — `applyPrMapGrouping` re-runs step 3 with its grouping, so a verb is only applied to an edge the links already justify, and any file it didn't place keeps its heuristic card. **As built (2026-10-05):** an unplaced *code* file whose module already has files in one of the model's groups joins the group holding most of them — on a large diff the model names a few files per area and stops, and a card per leftover module buried the areas it did name. Tests, config, docs and modules the grouping never touched still get heuristic cards. **As built (2026-10-06):** the prompt states the diff's size and a target group range (`targetGroupRange`), a soft cap of ~10 files / 600 changed lines per box, calls the starting cards a folder grouping to split freely, and asks for code deleted as a whole to get its own box. If one box still holds more than 40% of the files (and more than 15), the model gets one follow-up asking to split it; the second answer replaces the first only if it places as many files, has more groups and a smaller largest box. `applyPrMapGrouping` takes manifests, docs and tests back out of any AI group that holds code (a group of only non-code files keeps them), so they land on their own heuristic cards. Normalisation drops unknown paths, files placed twice, duplicate names, and labels that aren't a short lower-case verb phrase. Its tokens count toward the review's cost counter; "PR map" shows in the dock's running list while it runs. It never fails a review.

#### Storage and freshness

`(:PrMap)` (one per repo + review target, `-[:FOR]->` its `PullRequest` when there is one) stores only the AI **grouping** — names, descriptions, file lists, verbs, the model — never the assembled map, so cards, edges, context and +/- counts are always re-derived from the current diff and graph. It also stores `filesKey`, the sorted changed paths it grouped. The endpoint applies it only while the target's changed files are exactly that set; otherwise it serves the heuristic map with `aiOutdated: true` ("re-run the review to refresh it"). A re-run replaces it.

#### API

`POST /api/repos/[repoId]/pr-map` with the diff-impact body (`{prNumber}` | `{baseRef, headRef}` | `{filePaths}`) → `{nodes, edges, source: "heuristic" | "ai", model?, aiOutdated?}` (wire types in `components/graph/pr-map-types.ts`). Read-only. The changed files (status, counts, patches) come from `listTargetChangedFiles` (`lib/jobs/changed-files.ts`), cached for 30 s, since the tab asks again on every review state change. 400 for a fixable access problem (no PAT, PR on a local repo).

#### Rendering

`PrMapCanvas.tsx` uses **React Flow** (`@xyflow/react`) with **elkjs** (layered, left-to-right), not Cytoscape: a card holds clickable file chips, which is HTML, and the map is small enough that DOM nodes cost nothing. Layout is two-pass — every card is rendered offscreen at the fixed card width and measured, ELK places the measured boxes, React Flow draws them — and nodes aren't draggable. elkjs is loaded on first layout. Colours come from the app's CSS tokens (React Flow's un-suffixed `--xy-*` variables); edge colours are literal because React Flow writes marker colours into SVG attributes.

Covered by `npx tsx lib/jobs/smoke-test-pr-map.ts` (builder, normalisation, and the real client against the mock server, which answers `TASK: pr-map` by renaming the heuristic cards).

#### Areas: the PR view as one workbench (built 2026-10-05)

Decided with the user from mockups (a "workbench" with tables, and a "signal" graph with badges), kept inside the existing three-column layout. A PR map card is now an **area** of the change, and the canvas, the review dock and the right column read one object for it — `buildPrAreas` (`components/graph/pr-areas.ts`): each card's files, +/− and findings by bucket (defect / concern / unknown / OK-or-resolved), the card a finding belongs to (its file's card, else the card holding most of its component's code, else the unchanged neighbour it is), and the card's links in words.

- **Cards** (`PrMapNode.tsx`) are small: name, files and +/−, a thin severity bar, and the open defects + concerns as a badge in the corner. The file rows left the card — they live in the inspector and the dock's Files tab. Clicking a card **selects the area**: the others fade, its edges light up, the dock scopes to it, the inspector explains it. Clicking it again, the background or "Show the whole PR" goes back. (This replaces "clicking a card selects its component".)
- **Inspector** (`PrAreaPanel.tsx`): the area's description, its links ("→ updates Database"), files / lines / need-a-look, its components as chips (a chip narrows the dock to that component and focuses the chat on it), and its most-changed files (each opens the diff). With nothing selected there is no inspector and the chat takes the whole right column (2026-10-14: the worst-first area list was dropped — it repeated the cards, and the dock already puts exceptions first).
- **Dock** (`ReviewPanel.tsx`) has two tabs. **Findings**: four toggle chips (several can be on), OK hidden by default behind "Show N OK", rows on a badge · what · where · actions grid (where gets its own column once the dock is wide enough — a container query). Impact findings are **grouped by the declaration they use** ("`isPendingJobState` was removed from lib/jobs/queue.ts — 11 lines in 7 files still use it"), read back from the summary and rationale impact.ts writes (`impactSymbol`, `impactChange`); a signature change shows its before/after when expanded, every call site is a chip that opens its file, and Resolve resolves the group. **Files**: every changed file sorted by churn, with its area (or component, inside an area), +/−, a churn bar and its open findings. Both tabs follow the selected area and component; a scope chip clears it.
- **Verdict** (`ReviewSummary.tsx`) moved to the top of the diff summary in the left column, larger: "24 need a look", the per-bucket breakdown, and the PR-level "Delivers what it describes?" answer as one word ("Mostly.") plus its summary and confidence. The dock no longer repeats it.
- The map gets half the tab instead of 58% so the dock's tab bar and column headers leave room for rows.

**Second pass, closer to the mockup (same day).**
- **The repo moved into the top bar.** Name (the repo switcher, `app/repo-switcher.tsx`), source path or URL, the status dot and word, and Re-analyze / Remove as icon buttons now sit at the right of the app's top bar on every repo page, through a parallel-route slot: `app/@nav` (`repo/[repoId]/repo-nav.tsx`, one page per repo route — a catch-all is refused next to the repo's own index route — and explicit empty pages for `/` and `/settings`, because on a client-side navigation a slot with no match keeps showing what it showed). The repo layout and the slot share one request-cached lookup (`app/repo/[repoId]/load-repo.ts`), which is also where the auto re-analysis is enqueued. The repo header row is gone, and the top bar is 48px and spans the window on the Graph tab (`group-has-[[data-wide-shell]]`).
- **One toolbar per view.** The App map / Repo / PR switch is handed to each view as `leading` and drawn first in that view's own toolbar, so the switch and the view's controls are one full-width bar (`view-chrome.ts`: `VIEW_TOOLBAR`, `VIEW_CANVAS`), and every canvas runs edge to edge under it — no rounded box, no column padding. The side columns and the dock are the panel colour; the canvas is the darker dotted ground.
- **Left column.** The diff is a picker-style button (`#2 title ⇅`, reopens the picker) with mono lines under it — author · state · when, head → base, files · components, +/− — from the PR list's summary. Section heads (Checks, Before / after, Not on the map, Delivers what it describes?) are small uppercase labels with the result beside them; the verdict above is the only large type.
- **Cards** keep their files and +/− line when zoomed out (it scales like the status words instead of hiding), and the open-findings badge is sized in `em` so it scales with them.
- **New and deleted areas (2026-10-06).** A card whose files are all added gets a faint green edge and glow and says "new" before its file count; one whose files are all deleted gets the same in red and says "deleted" (`areaLifecycle` in `pr-areas.ts`, `LIFECYCLE_STYLES` in `PrMapNode.tsx`). Mixed cards stay neutral. The glow is deliberately fainter than the findings badge, the legend explains it only when the map has one, and the inspector repeats the word. A card's +/− shows only its non-zero side.

**Review pass (2026-10-06).** From a design review of the page:
- **Every toolbar is one row** at 1440px (PR 44px, App map 44px, Repo 45px), with a hairline after the view switch. Legends float over their canvas (the PR map's top right, the Repo graph's impact filters and review legend bottom left). Repo: icon-only layout buttons, the labelling stats as numbers with the words in a tooltip, shorter button words (Relabel, Collapse, Merges, Regroup). App map: a narrower search ("Find…"), Highlight, Describe; the "guessed from paths" note shows in words only on wide screens, else as an info icon with the same words.
- **No PR toolbar row (2026-10-14).** The PR map's Neighbours and Files/Functions controls sit at the right end of the view tabs (portalled from `PrMapCanvas` into GraphView's tab-bar slot, only while PR is the active view). The counts, the grouping note and the base/head structure note moved behind one info icon beside them, its hover listing them; it turns into an amber warning when the comparison failed, a new import cycle appeared or the review's grouping is outdated.
- **Panels and toolbar cells (2026-10-14).** The Graph tab is drawn as panels on a darker gutter: the diff column, the map, the review dock, the inspector and the chat each get their own bordered panel, so the gaps separate them rather than hairlines (globals.css, keyed off GraphView's `data-pane` / `data-pane-part`); the left column's sections are soft groups and the canvas dot grid is fainter. In every view's toolbar (`VIEW_TOOLBAR`, now `view-toolbar`, 36px, no vertical padding) the buttons, segmented switches and search fields run the bar's full height as square cells with side borders; plain text in it stays centred.
- **The dock header is one row** (34px, was 71px): empty severity chips are left out, Expand is an icon, and "reviewed at <sha>, <when>" plus the cost moved into Re-run's tooltip.
- **Keyboard triage in the dock**: J / K move through the visible rows (the current one is ringed and kept in view), Enter expands, R resolves or reopens (a whole caller group at once), D opens the file. Ignored while typing, while a dialog is open, and on the Files tab. A "j k ↵ r d" hint sits in the column header.
- **Checklist**: says "not judged yet" once the review is done (it used to say "waiting for the review to finish" forever), "judged once the review finishes" only while one runs; Judge is a ✦ icon beside the Checks heading instead of a box under the list; its icons are 24px.
- **Smaller fixes**: the verdict breakdown never splits a number from its word; "Commits · 19 files · 6 components" on one line; zoomed-out card names hyphenate instead of breaking at an arbitrary letter; line numbers and path folders use the normal muted colour (the faded ones were under 3:1 contrast).
