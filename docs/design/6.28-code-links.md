# 6.28 Code links: clickable imports and names, and usages, in the code views

*Built 2026-10-18.*

Every code view (the file viewer's File, Base and Diff tabs, the Files view
and the all-files reader) turns two kinds of text into links:

- **Import specifiers** that resolve to a repo file (`"./db/client"`,
  `.pkg.models`, `com.acme.Foo`, a Go module path) open that file.
  Package imports (`react`, `fastapi`) stay plain.
- **Names that lead to a declaration** open the declaring file at the
  declaration's line. That covers imported names, on their import line and
  every use; namespace members (`util.format`, followed through re-exports);
  and resolved calls, including calls to functions in the same file. A call
  to a class's constructor is linked by the class's name.

Names come only from the symbol graph's languages (TS/JS, Python, Java,
Kotlin). Specifiers work for every analyzer that resolves imports.

## Where the links come from

Nothing new is parsed, so `PARSE_VERSION` stays the same. The analysis
already has each file's resolved imports (`FileImport.resolvedPath`) and the
symbol graph's uses and calls (§6.10). `lib/analysis/code-links.ts`
(`buildCodeLinks`) turns them into per-file `CodeLink`s: the text as it
stands on the line, where it goes (`to`, `toLine`) and the lines it is a
link on. A language without symbol facts gives its imports no lines. The
viewer then links such a specifier wherever it stands quoted, or on a line
that reads like an import (`use`, `#include`, `@import`, …). No column is
stored: the viewer finds the text on the line itself.

They are stored per analysed commit, one row per file (`code_links`,
`code_link_sets`; `lib/db/code-links.ts`):

- **Repo tip:** written by the analysis job. The previous tip's set becomes
  a target set and ages out.
- **Review target:** the target-graph job writes both the merge-base and
  the head. The newest 10 target commits are kept.

`GET /api/repos/[repoId]/code-links?path=&sha=` reads one file's links,
defaulting to the analysed commit. If that commit has no set yet (it was
analysed before this feature), the answer is `state: "none"` and the code
shows plain until the next analysis.

## In the viewer

`components/graph/code-links.ts`:

- **Wrapping:** `linkLine` wraps each link in
  `<span class="code-link" data-link>` inside the highlighted HTML. The
  span is closed before every tag and reopened after it, like the diff's
  word marks.
- **Matching:** specifiers go first, then the longest names, and links
  never overlap. A specifier doesn't run into a longer path (`./a` vs
  `./ab`, `store` vs `store/sub`). A name has to stand alone (`connect` in
  `reconnect` isn't one) and is skipped inside a highlighted comment or
  string.
- **Clicks:** one handler on the table resolves the click through
  `linkFromEvent`. A click that ends a text selection does nothing, so
  dragging over code to copy it still works.
- **Which commit:** a whole file uses the commit it was read at. In the
  Diff tab, removed lines are read at the merge-base (under the old path
  for a rename) and context and added lines at the head.
- **Style:** a faint dotted underline at rest, solid in the brand colour
  under the pointer. The title names the target (`Open src/db/client.ts:12`).

## Where a click goes

- **File viewer (modal):** opens the target in the same modal. If the link
  has a line, it opens on the File tab scrolled to that line. The modal
  keeps the file the link was clicked in, and a **Back** button in its
  header returns there (a chain, so several hops unwind one by one). Any
  other way of opening a file starts a fresh chain.
- **Files view:** navigates there, at the line. A trail of up to 50
  positions backs the pane's **Back** button.
- **All-files reader:** a specifier pointing at another file of the diff
  jumps to it in the reader. A declaration's line, or a file outside the
  diff, opens in the file viewer on top.

## Usages

Each function, method and class gets an **"N usages"** button at the end of
its declaration line, in every code view. In the Diff tab it shows on
head-side lines only. A constructor has no button of its own: its calls
count for its class.

**What counts as a use** (`buildCodeUsages` in the same file):

- every line an imported name, or a namespace member, occurs on (import
  statements left out);
- every resolved call;
- in the declaring file, every other line the name occurs on.

The last one is read lexically, so a local variable with the same name
counts too. Instance calls the symbol graph can't resolve, and uses from
outside the repo, don't count. The empty dialog says so.

**Storage:** the per-file `code_links` row also holds the file's
declarations with their counts. Where each declaration is used goes into
`code_usages`, one row per declaration, and is pruned with the rest of the
set.

**Reading it:** `GET /api/repos/[repoId]/code-usages?id=&sha=`
(`lib/jobs/code-usages.ts`) reads the declaration's source and the using
files at that commit. It uses `git show` in a local repo's checkout or the
app's clone, and the host's API otherwise.

- Only the first 40 files are read, with up to 25 uses each; later files
  are listed by line number.
- The source is cut off after 200 lines.
- Each use is shown with 2 lines above and below. Windows that overlap or
  touch are merged into one block.

**The dialog** (`components/graph/UsagesDialog.tsx`) shows the
declaration's source at the top, with **View source**. Below it is every
file that uses it, the declaring file first, then by path. Each use line
is tinted, its name marked, and its line number clickable. Each file has a
**View file** button that opens it at its first use.

**Where View goes:** the view the dialog was opened from opens the file at
that line, the same way a followed link does (Back included), and marks the
used name on the ringed line (`markNames`). The reader's dialog opens the
file viewer.

Checked by `lib/analysis/smoke-test-code-links.ts`.
