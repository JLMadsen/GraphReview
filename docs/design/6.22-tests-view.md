### 6.22 Tests: a test inventory, what reaches the code, and what a change does to its tests (built 2026-10-17)

"Stats for testing". One Graph view, **Tests**, at the right end of the view row (**App map | API | Infra | Data | Env | Files | PR | Tests**). It's a full-column list view (`LIST_VIEWS`) like Env. With no diff selected it shows the repo's last analysed commit. With a diff selected it opens on **Change** (the change's test signals and the AI test plan), with **Repo** one click away.

**Static only.** Nothing is run: no test runner, no coverage tool. A coverage report counts only when it is **committed** (analysis reads git objects, §6.10). A git-ignored `coverage/` folder on the user's disk is invisible, like a git-ignored `.env.local` (§6.15).

#### 1. Reading (cached by blob; `PARSE_VERSION` 12)
- **Which files are tests** (`lib/analysis/tests/classify.ts`): the PR map's `classifyPath` patterns (§6.4) move here and gain Cypress's `.cy.*`. `__mocks__`, `testdata`, `fixtures` and helpers in a test folder are **support**: they're not code (never "untested"), and not tests (never a starting point for reach) unless they hold test cases.
- **Per test file** (`tests/facts.ts`, a lexical scan beside each parse, kept in the parse cache as `tests`):
  - **cases**: `it(`/`test(` (with `.each`, `.concurrent`, …), `def test_…`, `@Test`/`@ParameterizedTest`, `func Test…(`
  - **markers**, each with its line:
    - skip: `describe/it/test/context/suite.skip`, `test.fixme`, `xit`, `xdescribe`, `xtest`, `xcontext`, `@Disabled`, `@Ignore`, `@pytest.mark.skip`/`skipif`, `pytest.skip(`, `@unittest.skip`, `t.Skip(`/`Skipf`/`SkipNow`
    - focus: `.only`, `fit(`, `fdescribe(`, `ftest(`
- **Frameworks** (`tests/frameworks.ts`), each with the manifest or config that names it and its root folder:
  - Jest, Vitest, Playwright, Cypress, Mocha, `node:test`: `package.json` dependencies and scripts, `jest|vitest|playwright|cypress.config.*`, `.mocharc*`
  - pytest: `pytest.ini`, `conftest.py`, `pyproject.toml` `[tool.pytest…]` or a pytest dependency, `setup.cfg`/`tox.ini` `[tool:pytest]`/`[pytest]`, `requirements*.txt`
  - JUnit: `pom.xml`, `build.gradle(.kts)` naming junit
  - Go: `go.mod` with any `_test.go`
- **A test file's framework**: its imports first (`@playwright/test`, `vitest`, `@jest/globals`, `node:test`, `mocha`), then its language (`.go` → Go, `.py` → pytest, or unittest when no pytest is configured, JVM → JUnit, `.cy.*` → Cypress), then the nearest root's unit framework (Vitest before Jest before Mocha), or Playwright for an e2e path under a Playwright root.
- **Kind**: **e2e** for Playwright/Cypress, an `e2e/`, `cypress/` or `playwright/` folder, or `.e2e.`. **Integration** for an `integration/` or `it/` folder, `.int.`/`.integration.`, or JVM `…IT`. Otherwise **unit**.
- **Coverage reports** (`tests/coverage.ts`), at the repo root and each package root: `coverage/lcov.info`, `lcov.info`, `coverage/coverage-final.json` (Istanbul), `coverage/cobertura-coverage.xml`, `cobertura/coverage.xml`, `coverage.xml` (Cobertura / coverage.py), `target/site/jacoco/jacoco.xml` (JaCoCo). Plus any file with one of those names anywhere in the tree.
  - Kept per file: lines found, lines hit, the **missed** line numbers.
  - A report's paths are matched to repo files: as written, then relative to the report's package root, then by the longest unique path suffix. Unmatched entries are counted, not shown.

#### 2. The catalog (`buildTestsCatalog`, end of `analyzeTree`)
- `tests`: every test file with framework, kind, cases, LOC, markers and how many source files it reaches.
- `sources`: every **code** file (`classifyPath` = code, in a programming language) with LOC and the tests that reach it, **nearest first** (up to 20 kept, with the total), and the hop count to the nearest (1 = imported directly).
- **Reach** is a walk from each test file over the head's import edges (type-only ones skipped) and call edges (a call into another file), through support files, never through another test. Reachable is not covered: it means "a test loads this code", nothing more.
- `frameworks` and `reports` as read above.
- Stored for the default branch in `kv` under `tests-catalog:<repoId>` (no migration of its own). `ANALYSIS_VERSION` 13 re-analyses old repos so the catalog exists.

#### 3. The change (`compareTests(base, head, changed)`, in the target-graph job, stored as `tests` beside `env`)
- **Changed code**: each added or modified code file with its changed line count, the **unchanged tests** that reach it in the head (nearest first, up to 10, with the total), the **changed tests** that reach it, and, when the head's report covers the file, the changed lines it marks **missed**.
- **Deleted tests**: test files the base has and the head doesn't, with the files they imported directly that still exist.
- **Added / modified tests**.
- **Markers in the patch**: skip and focus markers on added lines of the head.

#### 4. Findings (`category: "tests"`, ids from the rule and the file:line)
Deterministic, no model call, synced by the target-graph job beside `env` (`STATIC_FINDING_CATEGORIES` gains `tests`, the dock's static chips gain **Tests**):
- **A focused test** (`defect`): `.only`, `fit`, `fdescribe` or `ftest` on an added line. The suite runs only that test and quietly skips the rest.
- **A skipped test** (`concern`): a skip marker on an added line.
- **A test file deleted** (`concern`): a deleted test whose directly imported files still exist in the head. The code it tested is still there, so its tests went with the file.
- **Changed code no test reaches** (`concern`): an added or modified code file that no head test reaches, beside tested files like it (some test reaches a code file with the same extension in the same folder, so `components/*.tsx` aren't held to a tested `components/util.ts`). Code in a folder no test reaches gets nothing: the Change list shows it as untested, and the inventory says it once instead of a finding per file. (A top-folder rule was tried first and fired on 52 of a real diff's 63 code files once a single file under `app/` was reached.) Files that declare only types and interfaces aren't code here: nothing in them runs.
- **Changed lines the coverage report misses** (`concern`): the head's report covers the file and marks every changed, instrumented line as missed. Partial misses are shown, not counted.

#### 5. AI test plan (`TASK: test-plan`, one call at the end of a review)
- Runs after the PR map pass, for PRs and ref comparisons alike, and only when the AI review ran. The inputs are the findings (not `ok`), the impact findings, the change's callers from the call graph, the API/schema/env/infra change lines, the "looks different" preview components (or the changed UI components when no preview has run), and the change's test signals (untested files, covering tests).
- The model answers one fenced JSON block: items with a title, steps (optional), a **type** (`regression` or `new-behaviour`), and a **source** (`finding`, `impact`, `caller`, `api`, `schema`, `env`, `infra`, `preview`, `untested`) with the reference it came from (a file, an endpoint, a component or a `#finding` id).
- Stored in `kv` under `test-plan:<repoId>:<targetKey>` with the head sha it was made for. A plan for an older head is shown dimmed as "for an earlier commit".
- **Report hook**: `loadTestPlan(repoId, targetKey)` and `testPlanMarkdown(plan)` in `lib/jobs/test-plan.ts` render the plan as a Markdown section, for the Markdown report to include.
- The mock server answers it with one regression item per finding/caller and one new-behaviour item per API change or preview component.

#### 6. Where it shows
- **Tests view** (`TestsView`). The toolbar holds **Change | Repo** (with a diff selected) and a search.
  - **Repo**: tiles (test files, cases, frameworks, unit/integration/e2e split, files a test reaches, report line coverage), an inventory table (framework × kind → files and cases, with the config file that names each framework), a per-component table (code files and LOC, test files and LOC, test : code ratio, % of files reached, report line %), the largest code files no test reaches, and every skip/focus marker in the repo.
  - **Change**: the test findings first, then the changed code files (untested ones first) with their covering tests and missed lines, deleted tests, added/modified tests, markers in the patch, and the AI test plan grouped by regression / new behaviour, each item linked to its source.
  - Files open in the file viewer at the line.
- **Chat**: `get_tests_for` (a file or component): the tests that reach it, nearest first, the hop count, report line coverage, and, in a PR chat, whether the change touches those tests.
- **Routes**: `GET /api/repos/[repoId]/tests` (the catalog joined with components) and `GET /api/repos/[repoId]/tests/plan?prNumber=|baseRef=&headRef=`.
