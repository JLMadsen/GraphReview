### 6.16 Infra sub-views: Diagram, Files, Requests (decided and built 2026-10-13)

The Infra view (§6.12) listed resources the way the tools see them: addresses, stacks, ×N, templated. A user who doesn't write Terraform or Kubernetes couldn't tell what the system looks like or what a change means. Three ways of looking were mocked up with the user and all three were kept, as sub-tabs beside the list. This reverses §6.12's "list only (no canvas)".

- **Where:** the Infra view's toolbar opens with **Diagram | Files | Requests | List** (remembered per browser, `graphreview.infra.mode`; Diagram by default). **Infra changes | All resources** applies to all four: outside List it means "only what the diff touches". The tool and environment filters are List-only. A resource opened from elsewhere (the left column's Infra section) switches to List.
- **Detail:** outside List, clicking a resource opens the existing `InfraResourceDetail` in a panel on the right.
- **No new analysis.** Everything is reshaped in the browser from the catalog, its links and the diff's plan (`infra-topology.ts`, `infra-explain.ts`). No `PARSE_VERSION` or `ANALYSIS_VERSION` bump.

#### 1. Diagram (`InfraDiagram`, `buildInfraTopology`)
- **Columns:** **Ways in** (routes by host: Ingress, HTTPRoute, Traefik tags, and Services of type LoadBalancer/NodePort), **Programs** (every resource with a `workload`: Kubernetes/Helm workloads, Nomad tasks) and **Data** (stateful, non-external resources that aren't workloads). Below them is **Platform and builds**: Terraform stacks, plus Dockerfiles only when the diff changes one. The changed resources and findings that sit in no column are listed on their stack's card.
- **Deploy sets:** a repo often declares the same programs several times (plain manifests, a Kustomize base, a Helm chart, a release folder). The diagram shows one stack's programs at a time, through a picker in the toolbar. The default is the set the diff touches, then a non-templated one (a Helm chart's links can't be read before it's rendered), then the one with the most programs. "All deploy sets" is the last option.
- **Edges, only certain ones**, each carrying how it was found:
  - **route:** a way in → its workload.
  - **calls:** a workload's env value names another workload's Service, its own name or a Nomad service (`CART_ADDR=cart:7070` → `cart`). The host part is read from `host:port`, URLs and `name.ns.svc…`.
  - **uses:** refs to a stateful resource (a PVC or volume), or an env value naming one. Drawn dashed.
  - **gone:** a calls/uses link that the base version of a changed workload had and the head doesn't (an env var the diff stops setting). Drawn red and dotted. Without it, the most important change of all, a broken link, would just disappear from a diagram of the head.
  - Terraform outputs wired into Kubernetes by CI stay unlinked.
- **The diff is painted on:** added green, removed red/dashed/struck through, changed and new versions with an amber edge, ⚠ for findings. "Only what changed" keeps the touched nodes and their direct neighbours.
- **Interaction:** hover lights a node's edges and neighbours. Clicking a node opens its detail. Clicking a route path follows it in Requests.
- **Size:** past 80 programs the column stops and asks for a search.
- **Drawing:** HTML columns plus one SVG overlay of bezier curves, measured from the nodes' boxes (`ResizeObserver`). There's no layout engine, so a calls arc within a column bows out to the right.

#### 2. Files (`InfraFiles`, `explainResource`)
- **Layout:** the infrastructure files on the left (changed and finding files first); on the right, the chosen file cut into **one block per resource**, starting at each resource's first line, with a plain-English note beside it. Nested resources (Nomad job → group → task, multi-document YAML) start their own blocks.
- **The note** is deterministic, never a model call:
  - a title saying what the resource is, by category and kind, with a short table of common Terraform types in words ("a managed Redis cache") and a fallback for the rest;
  - its links: the Dockerfile and code it ships, a port match or mismatch, routes and endpoints, env vars read but not set, or set but not read;
  - flags: stateful, prevent_destroy, conditional, templated, patched;
  - what the diff does (each attribute delta in words) and the findings.
- **With a diff:** a changed file shows its head with the removed lines put back in red where they were (`mergeWithPatch` in `diff-utils.ts`, from `diff-impact/file` and its `view=file`). Changed resources anchor on head lines. Unchanged and destroyed ones anchor on base lines through the merge. A file the diff deletes is shown whole, in red. With no diff, the file is read as analysed (`/file`).
- **Limit:** unchanged rows come from the analysed default-branch catalog, so a PR whose base is behind the default branch can misplace a note by a few lines.

#### 3. Requests (`InfraRequests`, `buildJourney`)
- **Pick:** a way in on the left, optionally narrowed to one endpoint under it (from the API catalog). On the right, it is followed hop by hop:
  - **DNS:** a Terraform DNS record whose attributes name the host.
  - **The route:** with its auth, or "No auth on the route itself".
  - **The program:** copies, and the port against the code's listen port.
  - **The build:** Dockerfile, the code folders it ships and what linked it, or why it couldn't be told.
  - **The handler:** for a chosen endpoint.
  - **Settings:** env vars the code reads that nothing sets, or "gets the N settings its code reads".
  - **Calls and data:** each target one level deeper, so "keeps data in …" shows where a called service stores its data.
- **Each hop** names its file:line (which opens the file) and, when it is a resource, opens its detail. Hop colours follow the diff (removed, finding, or gone link: red; changed: amber).
- **"Only what changed"** keeps the routes whose journey has an amber or red hop.

#### Checks
`npx tsx lib/analysis/infra/smoke-test-infra-views.ts`: a small Kubernetes app (Ingress → frontend, which calls cart through an env var → Redis on a PVC). The head stops setting `REDIS_ADDR`. Checked: the columns, the call/uses edges, the gone edge, "only what changed", the journey hops (port match, the flagged call), the notes (code link, finding, a Terraform type in words) and `mergeWithPatch`.

**Checked with a diff 2026-10-14** (microservices-demo, a branch that drops `CART_SERVICE_ADDR` from the frontend, changes a `targetPort` and adds a NodePort Service). Fixed on the way:
- A way in made by a LoadBalancer / NodePort Service carries that Service's diff state (added green, changed amber, removed red), and a changed one keeps its programs under "Infra changes".
- Changed boxes lost their amber left border: `border-border` after `border-l-warning` won the class merge. The order is now base colour first.
- A LoadBalancer or NodePort Service's note says it is reachable from outside, not only "inside the cluster".
- With a diff, "Sets …, which the code never reads" lists only names the head still sets (the links are the analysed commit's).
