### 6.19 Stats: numbers about the repo itself (built 2026-10-16)

A **Stats** page per repo (`/repo/[repoId]/stats`): static numbers about the codebase and its history, with no PR or diff involved. Asked for by the user (2026-10-16): lines of code per language plus a total, a contributor breakdown when more than one person committed, and a timeline of commits, pipeline failures and lines of code per day.

#### 1. What is counted (`lib/jobs/repo-stats.ts`)
- **Commit:** the last analysed commit, or the checkout's HEAD before any analysis (as the Files view, §6.14). Read with git from the app's clone (a local repo: the repo itself), so everything but CI works offline. The result is cached in memory per repo and commit; a commit's history never changes.
- **Lines per language:** `git grep -c -I -z -E -e "" <sha>` gives every text file's line count without reading blobs into Node. A second grep (`[^[:space:]]`) gives the non-blank count.
  - **Language** comes from the extension (or `Dockerfile`/`Makefile`/`Jenkinsfile` by name) through a fixed table, with linguist's colours and its kinds: **programming**, **markup**, **data** and **prose**. "Code" in the totals is programming only.
  - **Not counted:** lockfiles, `*.min.js|css`, source maps, snapshots, `*.d.ts`, and anything under `node_modules`, `vendor`, `third_party`, `dist`, `build`, `out`, `.next`, `.nuxt`, `coverage` or `__snapshots__`. Unknown extensions aren't counted either.
- **Contributors:** `git log --no-merges --numstat` over the whole history (`.mailmap` applies through `%aN`/`%aE`).
  - Identities are merged by email, then by name, so one person committing from two addresses is one row.
  - Lines added and removed count the same files as the language table, so lockfile churn doesn't dominate.
  - The section only shows with more than one contributor.
- **Timeline (per day):**
  - **commits:** non-merge commits per author-local date.
  - **lines of code:** the net change per day along the default branch's main line (`--first-parent -m`, so a merge counts as its diff against the first parent). It's anchored to today's total and walked backwards, so a cut-off history still ends on the right number.
  - **CI runs:** GitHub Actions workflow runs (`listWorkflowRuns`) or GitLab pipelines (`listPipelines`) on the default branch, the newest 1000. Their states are success, failure, cancelled and pending; a cancelled run isn't a failure. Legacy GitHub commit statuses have no history API, so they're not included. Local repos have no CI. The runs come from `GET /api/repos/[repoId]/stats/ci`, cached for 5 minutes, because they need the network; the git part is rendered on the server.
- **History cap:** 50,000 commits; past that, the commit count shows `+`.

#### 2. The page (`components/stats/StatsView.tsx`)
- **Totals:** lines (and non-blank), code lines, files and languages, commits and active days, contributors, and age since the first commit.
- **Lines of code by language:** a GitHub-style stacked bar, then a table with files, lines, non-blank and share. An **All files / Code only** toggle.
- **Timeline:** one SVG with three bands sharing a calendar x-axis (every day, with gaps filled):
  - lines of code as an area, carried forward over quiet days
  - commits as bars
  - CI as stacked bars, passed in green under failed in red; this band only appears when there are runs

  It has a 30d / 90d / 1y / All range switch. It opens on All for a repo younger than 90 days and on 1y otherwise. Hovering a day shows its lines, commits, CI counts and the names of its failed runs. The header sums the window: commits, CI runs and failures.
- **Contributors:** name, email, commits as a bar with a share, `+added −removed`, and the dates of the first and last commit.
- **Getting there:** a **Stats** link in the repo's top bar (beside Re-analyze), the palette's **Go to Stats**, and the repo item's → submenu.

#### Limits
- Line counts are physical lines, not cloc-style code/comment splits.
- Lines per day are only exact along the main line: work on side branches shows up on the day it was merged.
- CI history is limited to the newest 1000 runs and to the default branch.

#### Next (suggested, not built)
- **Churn hotspots:** the most-changed files over 90 days, weighted by size.
- **Change coupling:** file pairs that usually change together.
- **Bus factor per folder:** folders where one person wrote most of the recent lines.
- **Commit punch card:** weekday × hour.
- **Largest files and functions:** the largest files, and the longest functions from the parse.
- **Test-to-code ratio:** by test file conventions.
- **TODO/FIXME count over time.**
- **CI:** median duration, flakiest workflows (the ones that fail and then pass on the same sha) and time to fix a red main.
- **PR throughput:** time to merge, from the host.
