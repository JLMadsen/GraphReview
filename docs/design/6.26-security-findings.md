# §6.26 Security findings and hardening (built 2026-10-17)

A static finding category, `security`, written by the target-graph job
(lib/jobs/target-graph.ts) beside structure/infra/schema/env. No model call.

## 1. Diff-wide secret scan

lib/analysis/security/secret-scan.ts reads the `git diff -U0` text the job
already fetches and checks every **added** line in any file (code, test
fixtures, `.pem`, docs) for:

- known token shapes (`TOKEN_KINDS` in lib/analysis/env/secret.ts, shared
  with the env classifier): AWS, GitHub, Stripe live, `sk-`, GitLab, Slack,
  Google, SendGrid;
- PEM private key blocks;
- URLs with a password (local hosts and stock passwords skipped);
- a high-entropy value assigned to a secret-looking name (`apiKey = "…"`).

Skipped: lockfiles, `.min.js/.css`, `.map`, `.snap`, `.svg`, `.ipynb`, lines
over 2000 chars, and placeholders (`xxxx`, `example`, `<token>`, `changeme`,
`${VAR}`, low-entropy bodies like `ghp_000…`). At most 50 hits per diff.

Each hit is a certain `defect`. **The value is never stored**: summary and
rationale name the file, line and kind; the finding key uses a 12-hex
SHA-256 fingerprint. A line the env comparison already reported as
`committed-secret` (§6.15) stays that finding.

## 2. Endpoint auth findings (from the §6.11 API diff)

lib/analysis/security/findings.ts, `endpointAuthFindings`:

- `auth-removed` (defect): an existing endpoint's auth went from something to
  none — the change edited its registration lines, or replaced the auth with
  an explicit public marker (`@PermitAll`, `AllowAny`, `@Public`, …).
- `auth-unknown` (concern): from something to `?`, registration untouched.
- `new-endpoint-open` (concern): a new endpoint with no visible auth and no
  infra route with auth (§6.12 route links) covering it — only when other
  endpoints of the same framework have auth, or infra adds auth somewhere
  (an app with no auth at all would flag every route). More than six roll
  into one finding.

Server actions, internal and spec-only endpoints are left out.

## 3. Hardening

- GETs with side effects became POSTs (middleware blocks cross-origin
  non-GETs only): `/refresh` (`{ ifStale: true }` for the staleness check),
  `/preview/scan` (POST reads-and-starts; `previewAll: true` starts previews)
  and `/target-graph` (GET now reads only; POST starts). Left as they are:
  the repo detail read's stale-while-revalidate re-analysis (lib/jobs/repo-status.ts).
- MarkdownDoc no longer fetches remote images: a placeholder shows the alt
  text and URL; a click loads it once. Repo images still load from `/raw`.
- Optional MCP bearer token (lib/mcp/token.ts), off by default. Settings →
  Connect a coding agent turns it on, shows/regenerates it, and every
  harness snippet then includes the `Authorization` header. Stored encrypted;
  POST /api/mcp answers 401 without it.
