### 6.25 Onboarding and Graph navigation (built 2026-10-17)

From the 7-persona product review (2026-10-17): a first run gave no hint of what to set up, a missing AI provider only showed up as reviews that never ran, Stats was a lone link in the top bar beside the Graph tab's own view row, and a Graph view couldn't be linked or reached with Back.

#### 1. First-run hint (`app/page.tsx`)
- The repo list's **No repos yet** empty state has the Add repo button and, while no AI provider is active, one more line: reviews, labels and the chat need an **AI provider** (a link to Settings → AI providers), with a pointer to **Use local config** (§6.17).
- "AI provider set up" means an **active** provider is saved (`getActiveAiProvider()`); a saved provider isn't tested here. The status is read on the server (`app/setup-status.ts`), a boolean only — no secret reaches the page.
- A GitHub/GitLab token isn't mentioned up front: the Add repo dialog says when a URL needs one, and the PR features say so when one is missing.
- *Replaced (2026-10-17):* a three-step setup checklist above the repo list. Every step repeated something already on the page (the Add repo button, the AI off chip, the dialog's token note), and once done it stayed as a folded row on every visit.

#### 2. "AI off" chip (`app/ai-off-chip.tsx`)
- With no active AI provider, an **AI off** chip (warning tone) links to Settings → AI providers. It shows in the top bar's `@nav` slot, on the repo list and on every repo page. (It was once also on every repo card; dropped, as one chip per card said the same thing N times.)
- If the database can't be read, neither the hint nor the chip is shown (the page's own error state covers it).
- Not on Settings itself, where the AI providers card is the answer. The `@nav` slot re-renders per navigation, so saving a provider and going back clears it.

#### 3. Stats as a Graph view
- **Stats** (§6.19) is the last entry in the Graph tab's view row, after PR. The existing views keep their order. It is a list view (`LIST_VIEWS`): it takes the whole column, with no review dock under it, and mounts the first time it's opened.
- `components/stats/StatsGraphView.tsx` fetches `GET /api/repos/[repoId]/stats` (the git-only stats, previously rendered by the page) and frames `StatsView` with the shared view toolbar, which shows the commit the numbers are read at. It re-reads after a finished analysis.
- The top bar's **Stats** link is gone. `/repo/[repoId]/stats` redirects to `/repo/[repoId]/graph?view=stats`, so old links and bookmarks still work.
- Palette (§6.18): **Go to Stats** and the repo item's **Stats** switch the Graph tab to the view, like the other *Show …* commands (a `view` action with `view: "stats"`). For another repo's item it navigates to that repo's `graph?view=stats`. The chat's own tools don't offer Stats.

#### 4. The selected view in the URL (`useUrlState`, `components/graph/graph-view/view-state.ts`)
- The selected Graph view is mirrored into `?view=<app|api|infra|data|env|files|pr|stats>`; the Infra sub-view into `?infra=<diagram|files|requests|list>`. The other params (`?pr=`, `?base=&head=`) are kept, and the diff panel's own URL sync keeps `view`.
- **The URL wins**; without the param, the last choice remembered in localStorage is the default, as before. Every choice still updates localStorage.
- **History:** a click on a view tab (or a link into a view) pushes an entry, so Back/Forward switch views. The first push also writes the view being left onto the entry being left, so Back lands on it even if the page was opened without `?view=`. Arrow keys and switches that come with another change (a new PR check opening the PR view, an infra link opening List) rewrite the current entry instead, so they don't fill Back.
- **Opened on a view:** a page opened with `?view=` stays on it when its `?pr=` check finishes. Without the param, a finished check still switches to the PR view.
- Native `history.pushState` / `replaceState` keep Next's router in step (Next ≥ 14.1), so this needs no navigation and no server round trip.

#### 5. View tablist semantics
- The view row is a full ARIA tablist: each tab has an `id` and `aria-controls` pointing at **one** `role="tabpanel"`, the grid cell all views share, which is `aria-labelledby` the selected tab. (One panel rather than one per view, because views mount lazily: a per-view panel id would point at nothing until it's opened.)
- **Roving focus:** only the selected tab is in the Tab order (`tabIndex` 0, the rest −1). ←/→ move along the row with wrap-around, and Home/End jump to the ends. They select as they go (automatic activation) and move focus with the selection.

#### Limits
- The App map mounts before the URL is read on the first render, as it did before with the stored view, so a page opened on another view still loads the App map's data in the background.
- `?infra=` stays in the URL after leaving the Infra view. It only matters to the Infra view.
