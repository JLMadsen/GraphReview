### 6.12 Infrastructure as code: an infra catalog and what a change does to it (decided 2026-10-08, built 2026-10-10)

The API catalog's counterpart for the code that deploys the app: what infrastructure a repo declares, how it links to the app's own components, and what a PR does to it, read like a `terraform plan`. Decided with the user up front (2026-10-08):
- **Tools in v1:** Terraform / OpenTofu, Nomad jobspecs, Kubernetes manifests, Kustomize and Helm charts, and **Dockerfiles**: they link images to code, and since 2026-10-10 they're also **listed** in the view as resources (stages, base images) with their changes in the plan. Docker Compose, Packer, CloudFormation, Pulumi/CDK and Ansible are out of v1.
- **Settled 2026-10-10:** list only (no canvas — superseded 2026-10-13 by the Diagram, Files and Requests sub-views, §6.16); the left column's Infra section shows only when the diff changed infra; deterministic findings are passed to the review as already reported, so the model doesn't repeat them. Infra is built **before** the DB schema (§6.13) and claims `PARSE_VERSION` 4, `ANALYSIS_VERSION` 4 and SQLite migration 4.
- **Where:** a fourth Graph view, **App map | API | Infra | PR**: a list whose rows open in place, like the API view. On a PR it opens on a plan-style list of the infra changes.
- **Findings:** only a few **certain** ones (§5 below). Everything else is shown, not counted. No policy scanner (public buckets, `0.0.0.0/0`, IAM wildcards); that's tfsec/checkov territory, and the AI review gets the infra context.
- **Links to code:** deploys (image → component), env vars set against env vars read, routes onto the API catalog, and ports.
- **Static only, always:** no `terraform init`/`plan`, no providers, no state, no module downloads, no `helm template`. That works air-gapped and needs no cloud credentials.

#### 1. Reading the files (parse worker, cached by blob; `PARSE_VERSION` 4)
- **HCL** (`lib/analysis/syntax/hcl.mjs`). `@vscode/tree-sitter-wasm` ships no HCL grammar, so this is a hand-written lexical reader, as for Kotlin (§5). HCL's grammar is small: blocks with labels, attributes, expressions, heredocs and `${}` / `%{}` templates. Expressions are kept as text plus the **traversals** they contain (`aws_x.y.attr`, `var.n`, `local.n`, `module.m.out`, `data.t.n.attr`, `each.*`, `count.index`). Files: `*.tf`, `*.tf.json`, `*.tfvars`, `*.tfvars.json`, `.terraform.lock.hcl`, `*.nomad`, `*.nomad.hcl` and Nomad JSON jobs.
- **YAML** (js-yaml, multi-document): Kubernetes manifests (any YAML with `apiVersion` + `kind`), `kustomization.yaml`, Helm's `Chart.yaml` and `values*.yaml`. Helm `templates/` aren't YAML until rendered, so they're read by line: the `kind:` of each document, the `.Values.*` paths used and `include`/`template` calls. They are marked **templated**.
- **Dockerfile** (`Dockerfile`, `*.Dockerfile`, `Containerfile`): line reader for stages, `FROM` (image and tag/digest, or an earlier stage), `COPY`/`ADD` sources (and `--from`), `ENV`, `ARG`, `EXPOSE`, `USER`, `CMD`/`ENTRYPOINT`.
- **Code facts** (new in the existing extract, TS/JS, Python, Java/Kotlin, Go): env var reads (`process.env.X`, `process.env["X"]`, `import.meta.env.X`, `os.environ[...]`/`.get`/`getenv`, `System.getenv`, `os.Getenv`), Spring `${X}` placeholders, and listen ports where they're literal (`listen(3000)`, `PORT ?? 3000`, `uvicorn.run(port=)`, `server.port`).

#### 2. The catalog (`lib/analysis/infra/`)
`buildInfraCatalog` runs at the end of `analyzeTree`, beside `buildApiCatalog` (`AnalysisResult.infra`). Resolvers over the facts (a resolver that throws costs only its own resources):
- `terraform.ts`. A **stack** is a folder of `.tf` files that no other folder calls as a module.
  - Local module `source`s are followed with their inputs. Registry and git modules are **external** nodes carrying their version constraint. `.terraform.lock.hcl` gives provider versions.
  - Resource addresses are `module.<m>.<type>.<name>`. `count`/`for_each` show as **×N** (or ×? when not a literal), and conditionals as **conditional**. Nothing is evaluated.
  - Variables and their defaults; values per environment come from `*.tfvars` (an environment = a tfvars file). Locals, outputs, data sources, providers and the backend.
  - `moved`, `removed` and `import` blocks; lifecycle `prevent_destroy`, `create_before_destroy` and `ignore_changes`.
  - Edges: references, `depends_on` and module wiring.
- `nomad.ts`: job → group → task, with type, datacenters, `count`, driver and image/artifact, resources, network ports (static/dynamic, `to`), `service` blocks (provider, port, tags, checks), `env`, `template` (destination, `env = true`, and the Vault/Consul/Nomad-variable paths it reads), `vault` policies, volumes, constraints, and `update`/`migrate`. Levant/nomad-pack `[[ ]]` is marked **templated**. HCL2 `variable`s are read as in Terraform.
- `kubernetes.ts`: workloads (Deployment, StatefulSet, DaemonSet, Job, CronJob) with containers, images, env (literal, `valueFrom` secret/configMap ref, `envFrom`), ports, resources, probes and replicas; Service; Ingress / Gateway API `HTTPRoute`; ConfigMap; Secret (key names only, never values); PVC; HPA.
  - Kustomize: resources, bases, overlays as environments, images, patches and `namePrefix`. Patches are applied where they're strategic-merge on a known field; otherwise they're marked **patched**.
  - Helm: one stack per chart (its dependencies, values files as environments) and the templated resources from `templates/`.
- `docker.ts`: Dockerfiles with their build context and the folders they `COPY`. Each Dockerfile is a stack (`docker:<path>`) whose resources are its **stages** (`docker:api/Dockerfile:build`, `…:runtime`, or `stage0` when unnamed), each carrying its base image, `ENV`/`ARG`, `EXPOSE`, `USER` and entrypoint. Base images are **external** nodes with their tag or digest.
- **Resource ids** are stable across commits: `tool:stack:address` (`terraform:infra/prod:module.db.aws_db_instance.main`, `nomad:jobs/api.nomad:api/web/server`, `k8s:deploy/base:Deployment/api`).
- **Stateful** kinds are flagged from a short built-in list (databases, buckets, disks/volumes, queues, KMS keys, DNS zones; StatefulSet, PVC; Nomad host/CSI volumes). It's extensible and never a guess from names.

#### 3. Links to code (`link.ts`)
Each link carries how it was made, and an unresolved link says so instead of being dropped:
- **Deploys:** a task/container image → a Dockerfile (an image name built in the repo's CI files or `docker build -t`, a matching repo/folder name, or a Nomad `artifact`/`build` path) → its build context and `COPY` sources → the components those files belong to. The App map gets "ships as Nomad job `api` · k8s Deployment `api`" in a component's explainer.
- **Env vars:** names set per workload (job/task `env`, `template` with `env = true` where the keys are literal, k8s `env`/`envFrom` with known ConfigMap keys, Dockerfile `ENV`, `.env.example`) against names read by the components that workload deploys. Gaps are shown both ways: **read but not set** and **set but not read**. `envFrom` a Secret or a templated source counts as "maybe set", so it is never reported as missing.
- **Routes:** Traefik tags (Nomad/Consul), Ingress and HTTPRoute host + path → endpoints of the API catalog under that prefix. Middleware/auth annotations on the route (Traefik `forwardauth`/`basicauth`, ingress auth annotations) fill the endpoint's auth where the code showed `?` (§6.11's gateway limit).
- **Ports:** container/task port mapping and service target port against the app's literal listen port. A mismatch is shown, not counted.

#### 4. Storage and the change
- The default branch's catalog goes in an `infra_catalogs` table (one row per repo, `repo_id`/`sha`/`computed_at`/`data` like `api_catalogs`; SQLite migration 4; `ANALYSIS_VERSION` 4). The comparison is stored as `infra` in the `target_graphs` row's data, beside `api`.
- The target-graph job adds `infra: compareInfra(base, head, changed)` (`infra/compare.ts`), as plan-style entries per resource: **create**, **destroy**, **update** (a before/after attribute table: + green, − red, ~ amber), **moved** (a `moved` block, or Kubernetes/Nomad names that are unchanged at a new path), module/provider **version** changes, and Dockerfile base-image changes (`FROM node:20 → node:22`) as version entries. "Replace vs update in place" needs provider schemas, so it isn't predicted, only flagged for attributes on a short built-in force-new list. Link deltas (an env var newly unset, a route moved to other endpoints) go beside them.

#### 5. Findings (`category: "infra"`, ids derived from the resource, like structure findings)
Only certain ones, each without a model call:
- **A Terraform resource renamed without a `moved` block**: an address gone from the base and a new one of the same type in the same stack, with matching attributes, and no `moved` between them. Terraform would destroy it and create it again. (`concern`)
- **A stateful resource destroyed**, or `prevent_destroy` removed from one. (`concern`)
- **An env var a deployed component reads that its workload no longer sets**: the change removed the setting, or added the read, and no "maybe set" source covers it. (`concern`; only when the deploy link is resolved)
- The review prompt of each affected component lists these findings as **already reported**, and is asked not to repeat them (decided 2026-10-10).

#### 6. Where it shows
- **Infra view** (`InfraView`): the toolbar has the view switch, then with a diff selected **Infra changes N | All resources M**, then tool and environment filters and search.
  - "All resources" groups by stack → module/job/chart. A row is the tool icon, kind, address, and tags (×N, conditional, templated, stateful, external).
  - A row opens in place: its attributes (values per environment when they differ), what it references and what references it, its code links (deploys, env, routes, ports) and the file:line.
  - "Infra changes" is a flat list ordered destroy → moved → update → create, findings first, with the changed rows open (up to 8).
- **Left column:** an "Infra" section with `+1 −0 ~2` and the changes, **only when the diff changed infra** (as for API and Schema). Each line opens the view at that resource.
- **App map explainer:** "Deployed as" and the env vars the component reads but nothing sets.
- **Review:** each component's prompt gets the infra changes of the workloads that deploy it, plus env/route/port link deltas. Infra files themselves form their own component(s) (their folder), so a PR touching only `infra/` is still reviewed, with the plan-style change as its context. The intent check gets the whole list.
- **Chat and MCP:** `list_infra` and `get_infra_changes`.
- **Routes:** `GET /api/repos/[repoId]/infra-catalog`.

#### Limits
- Nothing is evaluated: `for_each` maps, `dynamic` blocks, functions, conditionals and Helm templates show as written. Kustomize patches beyond strategic-merge on known fields aren't applied.
- Remote modules and charts aren't fetched (air-gapped). Their insides are unknown, and so are links through them.
- No state: drift between code and the real infrastructure is invisible, and so are resources made outside the repo.
- No provider schemas, so there's no exact replace-vs-update and no attribute validation.
- Env var names built at runtime (`process.env[name]`) and image names from CI variables stay unresolved.

Covered by `npx tsx lib/analysis/infra/smoke-test-infra.ts`: one fixture per tool (a Terraform root with a local and a registry module, tfvars environments and a `moved` block; a Nomad job with Traefik tags and a Vault template; a Kustomize base/overlay; a Helm chart; a multi-stage Dockerfile), the links against a small app, and the comparison with each finding.

#### As built (2026-10-10)
Built as specified above; where the build differs or the spec was silent:
- **Reading.** Infra files are read by lexical readers **in-process** (like Kotlin's `analyzeSource`), not in the parse worker, and cached in the same `parse_cache` by blob (`PARSE_VERSION:infra-<reader>:<blob>`; a YAML file's key also says whether it is a Helm template, values file, kustomization or Chart.yaml, since that depends on its name and siblings). `lib/analysis/infra/read.ts` decides which paths are infra; `hcl.mjs` reads HCL (strings that contain nomad-pack `[[ var "x" . ]]` with inner quotes included). nomad-pack templates (`*.nomad.tpl`) are read too, marked templated. A generic `*.hcl` counts only when it has a `job` block.
- **Code facts** (env reads, literal listen ports) are a **lexical scan** run beside each code file's parse and cached with it (`FileAnalysis.code`, `infra/code-facts.ts`), not part of `extract.mjs`: Go has no symbol facts, and the patterns are one-line calls a scan reads as well as a tree. Comment lines are skipped. Spring placeholders are read from `@Value("${X}")` and from `application*.properties|yml`.
- **What links images to Dockerfiles:** `docker build|buildx build|podman build|buildah bud -t … -f … <context>` in Makefiles, `*.mk`, `*.sh`, `Jenkinsfile`, `justfile`, `.gitlab-ci.yml`, `package.json` scripts and `skaffold.yaml` artifacts; then a Dockerfile whose folder or name matches the image's last path segment, when exactly one does. **`.github/workflows` is not read**: the source tree skips dot-folders, so a repo that only builds images in GitHub Actions resolves by name only. Registry hosts, tags and `${VAR}` / `{{ }}` / `[[ ]]` parts are stripped before matching.
- **Infra files are graph files.** Terraform, Nomad, Kubernetes, Helm and Dockerfile files join `AnalysisResult.files` (language `terraform` / `nomad` / `kubernetes` / `helm` / `dockerfile`, no imports), so they cluster into their folder's module, map onto components, and an infra-only diff gets component reviews. Scripts, `.env.example` and Spring config are read for links but aren't graph files. The App map's heuristic layers put them in Infrastructure.
- **Kustomize:** `components:` (kind `Component`) are their own stacks ("kustomize component"), never bases, so they don't turn overlays into environments of themselves. An overlay's own manifests join its first base, marked `only in <env>`. Helm documents in one template file with the same kind and no literal name are numbered (`Service/services#2`); each document's attributes are the `.Values` paths **that document** uses (with its `{{ if }}` guard, which also marks it conditional).
- **Terraform:** variables, outputs and locals are listed for root modules only; a module's inputs show as the module call's attributes, and its resources under `module.<m>.…`. `terraform.tfvars` is an environment named `terraform.tfvars`. Values per environment are filled for variables and for root attributes that are exactly `var.x`. Docker image versions show a shortened digest (`20-alpine@sha256:dacac8e9a0df`).
- **Comparison:** base-image rows aren't compared (their change shows as the stage's `version` entry). A destroyed resource that a head `removed { lifecycle { destroy = false } }` forgets isn't a stateful-destroy finding; a rename that also destroys a stateful resource is one finding (the rename), not two. A destroyed resource with `prevent_destroy` counts as "stateful destroyed". Rename similarity: at least 80 % of attribute names/values equal, one best candidate. "Env no longer set" needs an env link at the base for the same workload, so a new workload never fires it. A finding about an unchanged resource (code that now reads an env var its workload doesn't set) is shown on that resource's row and in the left column as a "finding" line.
- **Findings** are synced as category `infra` by the target-graph job beside `structure` (stable ids from the target and rule, so replies survive), with `componentId` the file's owner. The review GET no longer counts static-analysis findings (`STATIC_FINDING_CATEGORIES`, `lib/db/types.ts`) as "already reviewed" — before, a target whose comparison wrote a cycle or infra finding never started its automatic AI review. The review dock's static chips are a list (`STATIC_CATEGORIES` in `ReviewPanel.tsx`): Structure and Infra.
- **Review prompt:** `ReviewRelatedContext.infra` and `.alreadyReported`, rendered as "Infrastructure this change affects" and "Already reported — do not repeat". Fixed on the way: `fitRelatedContext` (`lib/ai/review.ts`) rebuilt the related context from neighbours and files only, so the moved-code diffs (§6.10) and the endpoint lines (§6.11) never reached the prompt; it now keeps moves, endpoints, infra and already-reported untrimmed.
- **UI:** `InfraView`, `InfraResourceDetail`, `InfraChangesSection`, `useInfraCatalog`, `infra-view-model.ts`, `infra-types.ts`. Tool icons are lucide `Blocks` (Terraform), `Server` (Nomad), `Ship` (Kubernetes), `Anchor` (Helm), `Container` (Docker). The environment filter shows the stacks that have that environment and narrows the attribute table to it. Moved rows say `→`; update and version are `~`. With a diff selected, a row's code links still come from the **analysed default branch's** catalog (the change carries resources, not links). The API section in the left column now also shows only when the diff changed the API (no "comparing…" or "No API change" line). The API view's endpoint detail shows auth that only the infrastructure has (a Traefik auth middleware, an ingress auth annotation) as `… (infra)` where the code showed `?`; the endpoint's own `auth` isn't rewritten.
- **App map explainer:** "Deployed as" (the workload's address and stack) and "Reads env vars nothing sets" — names read by the card's files that the workloads deploying them don't set, or, for code nothing deploys, that no env source in the repo sets. Only when the repo has at least one env source; platform names (`NODE_ENV`, `NOMAD_*`, `KUBERNETES_*`, …) are never listed.
- **Chat:** `list_infra` (repo and PR chat) and `get_infra_changes` (PR chat); the PR chat's context carries the plan. **MCP:** `list_infra` (filter by tool or text) and `get_infra_changes`; the instructions describe the `infra` category.
- **Verified on real repos** (cloned to a scratch folder): GoogleCloudPlatform/microservices-demo (Terraform, Kustomize base + components + overlays, plain manifests, Helm chart, 21 Dockerfiles; 33 of 36 image deploy links resolved through `skaffold.yaml`, ports matched, real "read but not set" env flags), terraform-aws-modules/terraform-aws-eks (13 stacks, root module expanded into every example, 119 `moved` blocks), hashicorp/nomad-pack-community-registry (14 templated pack jobs), hashicorp-education/learn-nomad-getting-started (Nomad + three Terraform clouds), prometheus-community/helm-charts (46 charts, 582 templated resources). A 120-commit comparison of microservices-demo gave a plausible plan (image bumps, digest-only version entries, values changes only on the documents that use them); a test branch renaming a cluster, deleting the Memorystore instance and dropping an env var a Go service reads produced exactly the three findings, end to end in the running app (Infra view, left column, review dock, MCP).
