# 6.18 Command palette: one place to find anything and go there

Decided and built 2026-10-14.

## What it is

A palette that opens over any page with **Ctrl+Space** (or **Ctrl/Cmd+K**).
Its main job is to **navigate**: type part of a name, pick a result, land on
it. Commands (verbs) are second, behind `>`. It is the one search engine
behind the Files view's `t` and the repo switcher in the top bar.

| Prefix | Searches |
|---|---|
| (none) | everything below, grouped by kind |
| `>` | commands |
| `/` | files |
| `@` | symbols — functions, classes, types, constants (§6.10's declarations) |
| `#` | pull/merge requests, branches and commits |
| `!` | findings of the open review |
| `:` | endpoints (§6.11) |

Components, tables (§6.13), env vars (§6.15), infra resources (§6.12) and
repos show in the unprefixed search. The repo switcher opens the palette
scoped to repos; the `Search findings in all reviews` command scopes it to
every review of the repo. A scope shows as a chip in the input; Backspace on
an empty query drops it.

## Decisions

1. **Navigate first.** Result groups are ordered by their best match; commands
   rank below things unless the query starts with `>`.
2. **The keys fire everywhere**, text inputs included — nothing in GraphReview
   uses Ctrl+Space for autocomplete. Ctrl/Cmd+K is the same shortcut for
   anyone whose OS takes Ctrl+Space (macOS input sources, CJK IMEs).
3. **The current repo only.** Other repos are reached by switching (a repo
   result, or the switcher). Outside a repo, the palette lists repos and the
   commands that need none.
4. **Local data only — no network while typing** (the air-gapped target).
   PRs, branches and commits come from a per-repo snapshot (`kv`
   `palette:remote:<repoId>`) refreshed whenever the Pull Requests, Branches
   or commit-picker lists load, and by the `Refresh PRs, branches and
   commits` command; reviewed PRs in `pull_requests` are merged in.
5. **Safe actions only.** The palette navigates, starts a review (opening a
   PR does that, as a `?pr=` link already does), queues a re-analysis,
   refreshes the snapshot and marks a finding *fixing*. Anything destructive
   or that needs typed text opens the real UI.
6. **Which code.** With a review target open, symbols come from the target's
   head commit and the files and components it touches rank first; elsewhere
   from the analysed tip. When the head has no symbol index yet, the tip is
   searched, a row says so (`Analyse PR head` starts the comparison, §6.10),
   and the diff's paths still drive the ranking.
7. **Matching on the server, per keystroke** (debounced 80 ms): a subsequence
   `LIKE` pre-filter in SQLite, then a fuzzy score in TypeScript
   (`lib/search/fuzzy.ts`, shared with the client for highlighting).
8. **Open in…** Every result has a list of targets. Enter takes the first;
   **→** (with the caret at the end of the query) or **Tab** opens the list,
   **←**/Esc closes it, Enter picks. Ctrl+Enter opens the second target.
9. **Empty query**: the last picks in this repo, then context rows — the open
   review's open defects and `Ask chat` — then a line of prefix hints.
10. **History in SQLite** (`palette_history`, per repo, `''` outside one):
    uses and last use, which boost ranking.
11. **Chat hand-off.** In a repo, a row pinned under the results offers
    `Ask chat: <query>`. It is never selected by default, so Enter never
    spends tokens by accident; picking it sends the question to the Graph
    tab's chat — about the open review, or the whole repo with none open
    (going to the Graph tab first from another page). *Changed 2026-10-14:*
    first built for an open review only, at the bottom of the list, where it
    went unseen.
12. **A search box in the top bar** (`PaletteTrigger`) opens the palette
    with a click, for anyone who doesn't know the shortcut.

## Targets per kind

| Kind | Enter | Also |
|---|---|---|
| File | Files view at the file (a changed file: the file viewer's diff) | file viewer whole, App map card |
| Symbol | Files view at its line | file viewer at the line (changed file), PR map function (touched), App map card |
| Component | App map card (its PR area when the change touches it) | Files view at its folder |
| PR | open it on the Graph tab | open on GitHub/GitLab, copy link |
| Branch | compare with the default branch | Branches tab |
| Commit | compare with its parent | copy sha |
| Finding | the review dock, the finding active | its file at the line, its component, mark fixing |
| Endpoint / table / env var / infra resource | its view, the item focused | its file at the line |
| Repo | its Graph tab | Pull Requests tab, Branches tab |

## How it is wired

- `components/palette/CommandPalette.tsx` is mounted once in the root
  layout. It reads the repo from the URL and the Graph tab's context
  (review target, changed paths) from `components/palette/bus.ts`.
- Navigating actions reuse the chat's view actions (`ChatActionDTO`,
  §6.7): on the Graph tab they go straight to `applyChatAction`; from any
  other page the palette navigates to the Graph tab and leaves the action
  pending on the bus, and GraphView applies it once it can (actions about the
  change wait for the target).
- Switching the target (a PR, a branch or commit comparison) is a
  navigation to `?pr=` / `?base=&head=`; the Graph page keys GraphView on
  those params so it starts over on the new target.
- `POST /api/search` — `{ repoId?, q, scope, targetKey?, touched? }` →
  ranked items plus notices. `POST /api/search/history` records a pick.
  `POST /api/search/remote` refreshes the snapshot.
- Symbols are stored per commit in `symbol_index`, written by the analysis
  job (tip) and the comparison job (a target's head); a repo keeps its tip
  and its five most recent heads. A repo analysed before this existed has no
  index until its next analysis — a row says so and offers `Re-analyse`.

- Next/previous open finding as commands (the dock's own keys do it, §6.8).
