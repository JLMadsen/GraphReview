### 6.27 Acceptance criteria, judged one by one (built 2026-10-17)

The intent pass (§9.1) says whether the PR as a whole delivers. This adds a verdict per stated acceptance criterion.

**Parsing** (`lib/ai/acceptance-criteria.ts`, deterministic, PR targets only): the PR description and each linked GitHub/GitLab issue body. Three formats:

- `checkbox`: `- [ ]` / `- [x]` items anywhere. Ticked items keep `ticked: true` but are still checked against the code.
- `gherkin`: a Given/When/Then block (And/But continue it, an optional `Scenario:` line titles it) is one criterion. A ```` ```gherkin ```` fence counts too.
- `heading`: list items under a heading or label line (`## Acceptance criteria`, `**AC:**`, `Definition of done:`) until the next heading of the same or a higher level.

Code fences and HTML comments (template hints) are skipped. Nested items are folded into their parent. Criteria are deduplicated by folded text, numbered c1…cN, and capped at 30.

**Judging**: done in the existing intent call (`TASK: pr-intent`), since the call already has the diff and the findings and the criteria cost only a few hundred tokens. The criteria are listed in the user message, and the system prompt gets a `criteria` block before its Rules list (that list is left alone so it merges cleanly). Each answer is `pass | fail | unknown`, with a reason and evidence written as `path:start-end`. Evidence is kept only when the path is a changed file. **A pass with no valid evidence becomes unknown**, and the reason says so. An unknown with no evidence says "No evidence for it in the diff." Criteria the model skipped, unreadable replies and failed calls all come back as unknown.

**Storage**: `runIntentPass` returns the verdicts, and `review.ts` saves them as a `checklist_answers` row under the built-in item id `acceptance-criteria` (`ACCEPTANCE_CRITERIA_ITEM_ID`). Like any AI answer, the row is stamped with the reviewed head sha.

**Checklist card** (§6.6): `evaluateChecklist` parses the criteria fresh on every read and matches stored verdicts by criterion text, for the current head only. It returns a single item, "Acceptance criteria 3/5": it fails if any criterion fails, passes if all pass, and is otherwise pending or unknown. The item expands to one row per criterion. Each row has a verdict icon and a text label (Met / Not met / Can't tell / Not judged yet), the original text, its source, the reason, and evidence links that open the file's diff at those lines. The item is shown only when the PR states criteria, and it can't be edited or switched off. `useChecklist` refetches when a review completes. "Judge again" doesn't re-judge criteria; re-running the review does.

**Copy as Markdown**: the review report gets an "Acceptance criteria (n/m met)" section.

Tests: `lib/ai/smoke-test-acceptance-criteria.ts` covers parsing (all three formats plus none, dedup, fences and comments) and the mock round trip (the mock's verdicts follow `MOCK_CRITERION_FAIL` / `MOCK_CRITERION_UNKNOWN` in a criterion's text).

**Not built:** finding ids as evidence (only file and line evidence), and judging criteria from the checklist's own "Judge again" button.
