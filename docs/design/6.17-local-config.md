### 6.17 Use local config: AI providers from local harness configs (built 2026-10-14)

Settings → AI providers has a **Use local config** button beside **Add provider**. It scans the usual places coding harnesses keep their provider setup, lists what it finds, and loads the ones the user ticks as ordinary saved providers (one or more at a time). Nothing is linked: a loaded provider is a copy, and editing the harness config later doesn't change it.

#### Where it looks (`lib/ai/local-configs.ts`)
| Harness | Files | Default model |
|---|---|---|
| OpenCode | `~/.config/opencode/{config,opencode}.json[c]` (+ `$OPENCODE_CONFIG`), keys in `~/.local/share/opencode/auth.json` | `model` (`provider/model`); `small_model` second |
| Codex | `~/.codex/config.toml` (`$CODEX_HOME`), key in `auth.json` | `model`; `[profiles.*]` models after it |
| Claude Code | `~/.claude/settings.json` `env` + `model` | `ANTHROPIC_MODEL` / full `claude-*` ids (aliases like `sonnet` skipped) |
| Crush | `~/.config/crush/crush.json` (`%LOCALAPPDATA%` on Windows) | `models.large` |
| Continue | `~/.continue/config.yaml` (or `config.json`) | first model of each provider + endpoint |
| Aider | `~/.aider.conf.yml` | `model` |
| Copilot CLI | `~/.copilot/settings.json` / `config.json` | `model` |
| Environment | `OPENAI_API_KEY` (+ `OPENAI_BASE_URL`), `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`, … | none |

A harness's provider id (`anthropic`, `openrouter`, `ollama`, …) maps to its OpenAI-compatible base URL (`KNOWN_PROVIDERS`); a custom base URL in the config wins. Keys resolve the way the harness does: the literal, `{env:X}` / `$X` / `${X}`, OpenCode's `{file:…}`, the harness's auth file, then the provider's usual env var. Unreadable files are skipped silently.

#### The list
One row per candidate: suggested name, harness, base URL, the file it came from and where the key came from. Ticking a row shows the name (editable) and the **model: a dropdown of the models the config names, default first**; a free-text field when the config names none. A row whose base URL another saved provider already uses says so but stays selectable.

#### Keys
Keys never reach the browser: the scan returns `hasKey` / `needsKey` only, and the import action **re-reads the configs by candidate id** and encrypts the key straight from the file. A local server (localhost) with no key gets a placeholder. Anything else without a usable key — an OAuth sign-in (OpenCode's Copilot, Claude Code's account login, Codex's ChatGPT login), a Continue `${{ secrets }}` reference, Copilot CLI's keychain — shows a note and a key field to paste one into; it can't be loaded without it.
