### 6.14 Files: the repo as files (built 2026-10-11)

A fifth view in the Graph tab's view switch, **Files**, between Data and PR: the repo the way a code host shows it, for reading code without leaving the app. Like the other views it is the **last analysed commit** (before the first analysis: the checkout's HEAD), a full-column list view (`LIST_VIEWS`, no review dock), mounted on first open.

- **Data:** `GET /api/repos/[repoId]/tree` (`lib/jobs/repo-tree.ts` `listRepoTree`): `git ls-tree -r -l -z` in the analysis's own source (`sourceDir`: the clone, or the local repo) — every path with its size, symlinks and submodules marked, capped at 100,000 entries (`truncated`) — plus the commit's subject, author and date. Files open through the existing `/file` (same commit, 400 KB text cap). Images (`png jpg gif webp avif bmp ico svg`, ≤ 10 MB) come from `GET /api/repos/[repoId]/raw?path=&sha=` (`readRepoImage`, `git cat-file blob`), served only for those types, with `CSP: default-src 'none'; sandbox` and `nosniff` so an SVG opened directly can't script the app's origin; the sha is always the tree's, so responses are cached as immutable.
- **Layout (`FilesView`):** a folder tree on the left (the way to the current path opened); on the right a breadcrumb bar, then a folder's listing (folders first; a folder holding only one folder reads as one row, `src/main/java`) under a "latest commit" bar, with its README rendered below; or a file — line count, size, language, copy path / contents, syntax-highlighted lines (`FileText`, shared with the file viewer) whose numbers mark a line. Markdown files open on a rendered **Preview** (Code beside it); SVGs on the picture (Code beside it); other images as pictures. The current path is remembered per repo and browser.
- **README / Markdown rendering** is hand-rolled (no dependency, air-gapped target): headings (ATX, setext and `<h1>`…`<h6>` lines), paragraphs, nested and task lists, fences (highlighted), quotes, GitHub alerts (`> [!NOTE]` …), tables, rules, emphasis, inline code, links and images. Nothing is passed through as HTML: other tags are reduced to their text, `<img>` to an image. Links into the repo open in the view; `http(s)` / `mailto` links in a new tab; repo images load from `/raw`, `https` images as they are.
- **Go to file** (`t`): a fuzzy match on the path — a name prefix, then a substring of the name, then of the path, then the query's characters in order, tightest run in the name first. Arrow keys and Enter.
- **With a diff selected:** the files it touches are marked `M` (folders above them with a dot), the view opens on **Changed** (only those files; **All files** beside it), a changed file has **Show diff** (the shared file viewer on its diff), and files the diff adds — not in the analysed commit — appear as `new` and open on their diff.
- **Last commits** (added 2026-10-16): each row of a folder shows the newest commit that touched it — subject and age (author and sha on hover) — and the bar above a folder or file shows that folder's or file's own newest commit (the root: the analysed commit). `GET /api/repos/[repoId]/last-commits?dir=&sha=` (`lastCommitsIn`): the folder's names from `git ls-tree <sha>:<dir>`, then one `git log --name-only` down the folder's history, stopped as soon as every entry is attributed (15 s cap; the rest left blank). Cached per repo, commit and folder on the server and in the page, so a file reuses its folder's walk.
- **Not built:** blame, history, browsing other refs (the tree is always the analysed commit), and binary files other than images.
